# Двійково-кодовані перемикачі (BCD)

Прошивка підтримує до чотирьох незалежних перемикачів, кожен із 1–4 бітами.
Цей режим декодує **всі двійкові комбінації**, а не лише десяткові цифри 0–9.
Для N бітів створюється 2^N фізичних кнопок: 2, 4, 8 або 16.
Код 0 також є позицією перемикача й активує першу кнопку його групи.

## Налаштування пінів

Для кожного перемикача призначте рівно один пін кожному біту від `bit0`
до старшого біта без пропусків. `bit0` має вагу 1, `bit1` — 2,
`bit2` — 4, `bit3` — 8. Розташування пінів на платі та їхній порядок
у `pins[]` не визначають вагу біта.

Режим `BCD<n>_BIT<b>_VCC` означає активний високий рівень із внутрішнім
pull-down. `BCD<n>_BIT<b>_GND` означає активний низький рівень із внутрішнім
pull-up. Полярність можна змішувати в межах одного перемикача.
GPIO налаштовується так само, як для звичайних `BUTTON_VCC` / `BUTTON_GND`.

Наприклад, для чотирибітного перемикача, що замикає входи на землю:

```c
config.pins[0] = BCD1_BIT0_GND;
config.pins[1] = BCD1_BIT1_GND;
config.pins[2] = BCD1_BIT2_GND;
config.pins[3] = BCD1_BIT3_GND;
```

Активні `bit0` і `bit2` утворюють код 5. Він активує шосту фізичну кнопку
групи; усі інші кнопки групи відпущені. Самі біти не додають окремих кнопок.

## Контракт для конфігуратора

Розмір і порядок полів `dev_config_t`, тип `pin_t` (один байт), наявні
коди режимів пінів, версія прошивки та формат USB-звітів не змінені.
Нові значення додані після `UART_TX = 31` у `common_types.h`:

| Група | GND bit0…bit3 | VCC bit0…bit3 |
| --- | --- | --- |
| 1 | 32…35 | 36…39 |
| 2 | 40…43 | 44…47 |
| 3 | 48…51 | 52…55 |
| 4 | 56…59 | 60…63 |

Формула коду піна: `32 + (group - 1) * 8 + bit + (VCC ? 4 : 0)`.
Групи мають номери 1–4, біти — 0–3.

Порядок фізичних кнопок:

1. Матриці.
2. Регістри зсуву.
3. Кнопки з осей.
4. Звичайні одиночні кнопки.
5. BCD-групи 1, 2, 3, 4; у кожній — коди від 0 до 2^N − 1.

Невикористані групи не резервують кнопок. Для кожної використаної групи
конфігуратор має додати 2^N фізичних кнопок і налаштувати відповідні
`buttons[].physical_num` (індекси від 0). Логічні кнопки, інверсія,
таймери та shift-модифікатори працюють через наявний механізм.
Для звичайного вибору однієї позиції використовуйте `BUTTON_NORMAL`
без інверсії та додаткових таймерів.

Спільний ліміт усіх джерел — 128 фізичних і 128 логічних кнопок.
Чотири чотирибітні перемикачі займають 64 фізичні кнопки.
Конфігуратор слід навчити показувати нові режими, рахувати кнопки
та відхиляти пропуски бітів, дублікати й перевищення ліміту.
Його зміни не входять до цієї реалізації. Попередній конфігуратор
не вміє задавати нові режими; старі конфігурації працюють як раніше.

## Стабільність та некоректні конфігурації

Брязкіт обробляється для коду групи цілком за `button_debounce_ms`.
Будь-яка зміна коду починає відлік заново. До завершення інтервалу
зберігається попередня прийнята позиція. Після запуску кнопки групи
відпущені, доки не прийнято перший стабільний код. Зміна позиції
оновлює всі фізичні кнопки групи разом перед логічною обробкою.
За нульового інтервалу код приймається одразу.

Пропущений або повторно призначений біт робить групу неактивною;
інші коректні групи продовжують працювати. Її діапазон кнопок
резервується за найстаршим призначеним бітом. Якщо для повного
діапазону бракує місця, залишок буфера резервується з відпущеними
кнопками, без часткового декодування або виходу за межі буфера.

Конфігурація застосовується стандартним шляхом із перезапуском MCU.

## Перевірка

```sh
# З кореня репозиторію; host GCC, AddressSanitizer і UndefinedBehaviorSanitizer.
make -C tests test

# ARM-збірка в підготовленому хмарному середовищі.
bash /workspace/toolchains/build-freejoy.sh
```

Тести компілюють справжній `buttons.c` із заміною апаратного GPIO і часу.
Вони перевіряють усі коди й полярності для 1–4 бітів і всіх груп,
одночасну роботу чотирьох перемикачів, порядок фізичних кнопок,
брязкіт та проміжні коди, USB-звіт, переповнення лічильника часу,
некоректні конфігурації та межі буфера. Перевірка на STM32 із фізичним
перемикачем залишається окремою апаратною перевіркою.
